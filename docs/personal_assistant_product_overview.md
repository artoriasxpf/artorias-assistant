## 2. 产品介绍

### 2.1 一句话定义

**一款能理解用户需求，在授权范围内操作文件、使用工具和连接个人服务，并持续交付可查看、可追踪结果的个人助理 Agent。**

用户可以用自然语言提出需求，例如整理资料、生成报告、修改代码、处理邮件、准备社交内容或比较商品。助理结合会话上下文与用户选择的数据，完成必要的信息检索、分析和执行，将结果以回答、文件、变更记录或待确认动作交付。

产品以个人工作空间为持续工作的基础：用户今天生成的文件，明天仍能查看和继续修改；一次操作为什么发生、修改了哪些内容、是否仍在等待，都可以回到对应会话追踪。

### 2.2 核心价值

| 用户问题 | 产品提供的价值 | 可见结果 |
|---|---|---|
| 资料分散在目录、网页和账户中 | 在授权范围内统一查找、整理与关联 | 带来源的摘要、清单与文件 |
| 多步骤事务需要反复切换应用 | 通过一次需求描述组织工具操作 | 连贯执行过程和明确完成状态 |
| 对话中的建议还需要手工落实 | 直接生成、修改和保存可使用的结果 | 文档、代码、变更、草稿 |
| 无法判断 Agent 做到了哪一步 | 展示执行进度、等待原因和失败情况 | 工具状态、审批卡片、结果证据 |
| 担心文件改错或操作失控 | 控制授权范围、保存文件版本、提供适用的撤销 | 修改预览、历史版本与冲突提示 |
| 后续追问丢失原有背景 | 保存会话与项目上下文，按需关联历史 | 连续修改同一项目和产物 |

### 2.3 产品形态

初期：运行在用户电脑上的单用户应用，以 Web 页面交互，数据与受管文件保存在本机。Agent Runtime 使用 Deep Agents；若连接云端模型，必要的请求内容会发送给模型服务。

后期：云端主 Runtime 通过共享 Worker 承接执行，用户具有隔离的逻辑工作空间，本机 Device Agent 处理授权的设备操作。桌面、手机与 Web 可访问同一用户的会话和交付物。云端文件不会自动等于本机全部文件，需通过明确选择、上传或设备授权建立联系。

## 3. 目标用户与核心场景

第一阶段优先服务能够使用本地应用、经常处理资料和代码的个人用户，以「资料处理 + 受管文件操作 + 编程辅助」验证完整执行闭环。邮件、社交和购物属于后续扩展，不要求首版同时接入全部平台。

| 用户类型 | 典型需求 | 首要价值 |
|---|---|---|
| 知识工作者与研究者 | 阅读资料、检索网页、归纳结论、生成报告 | 减少收集与整理时间 |
| 开发者与技术学习者 | 分析项目、生成代码、运行检查、理解修改 | 让代码辅助可执行、可验证 |
| 个人事务管理用户 | 邮件整理、待办、日历、定时提醒 | 将信息转化为可跟进事务 |
| 内容创作者 | 整理素材、生成草稿、管理发布准备 | 在多个渠道复用内容 |
| 消费决策用户 | 商品对比、预算筛选、订单信息整理 | 提供有来源的决策依据 |

### 3.1 场景 A：资料整理与报告交付

输入：「阅读我选中的资料，结合相关网页，生成一份对比报告。」

助理确认可访问的文件范围，读取并按需检索，形成有来源引用的结论，保存报告并展示附件。用户随后要求补充某项指标时，继续引用已有文件和上下文，而不是要求重新上传全部材料。

成功标准：报告可打开，来源可追踪，缺失数据明确标注；最终附件关联固定版本，后续修改不改变旧回答中的交付物。

### 3.2 场景 B：代码项目创建与修改

输入：「在这个工作区创建一个简单项目，运行检查并解释修改。」

助理在受管目录生成文件，按需使用隔离执行环境运行代码，展示检查结果与文件差异。失败时说明实际错误及已完成的部分；用户可查看变更，或在没有后续冲突的条件下撤销。

成功标准：文件真实存在；声称运行成功时必须有实际执行结果；检查失败不伪报成功；撤销不能覆盖用户后续编辑。

### 3.3 场景 C：邮件与个人事务

输入：「整理本周未处理邮件，列出待办，为其中两封准备回复。」

用户连接并授权邮箱后，助理读取指定范围，输出摘要、待办和回复草稿。草稿、实际发送和发送结果分别显示。发送前按授权策略确认具体收件人与正文；超时且结果不明时先核对，不重复发送。

成功标准：每项结论能回到源邮件；回复内容可编辑；界面准确区分草稿与已发送。此场景属于账户连接扩展阶段。

### 3.4 场景 D：社交与购物辅助

社交示例：「把这份素材改写成适合两个平台的草稿。」购物示例：「按预算比较几个商品，列出差异和参考链接。」

第一步交付内容与比较结果，再按具体平台能力加入发布、收藏或订单信息管理。发布、私信、下单等有外部影响的操作需展示操作对象与最终内容，并按明确授权执行。平台未接入或权限不足时，应交付可用草稿或说明限制，不显示虚假的成功状态。

## 4. 功能体系

### 4.1 对话与需求承接

- 创建和管理会话，支持多轮追问、引用历史产物与选择工作空间。
- 接收自然语言需求和选定文件；展示输入已接收、排队、执行、等待与结果状态。
- 信息不足且影响执行时提出具体问题；可以直接推进的部分先完成。
- 支持取消请求；明确区分「已请求停止」与「执行已停止」。
- v1 同会话串行执行，普通新输入可排队；审批与取消不受普通消息队列阻塞。执行中的自由插话改目标列为后续能力。

### 4.2 文件与工作空间

- 浏览和读取已授权的目录或受管项目，支持文件查找、内容分析、生成与修改。
- 将会话产物、项目文件和临时内容区分管理，用户可查看产物和修改记录。
- 保存文件版本以及对应操作来源；受支持的修改可以预览差异和撤销。
- 同一项目可被多个会话继续使用，不要求每个会话复制一份项目。
- 外部目录访问受授权范围约束；首版不承诺对整个宿主机任意变化进行完整版本追踪。

### 4.3 网页检索与信息分析

- 通过已配置工具进行搜索与网页内容获取，结合用户文件进行归纳、比较和报告生成。
- 记录来源、获取时间及必要的引用；将无法访问、互相冲突和缺失的信息明确呈现。
- 按需加载资料，避免把整个项目或全部历史无差别发送给模型。
- 浏览器自动化作为进阶工具接入，只有普通获取方式无法满足需求时使用相应能力。

### 4.4 编程与执行

- 支持理解项目、生成代码、修改文件、运行检查及输出运行结果。
- 文件读写与程序执行分别授权；执行环境只在需要时分配。
- 执行失败时保存可用产物与日志摘要，让用户能继续修复。
- 代码执行能力须在隔离环境接入后上线；不以首版直接开放宿主机任意 shell 作为实现捷径。

### 4.5 邮件、日历与个人事务

- 邮件：授权连接、查询、摘要、分类建议、回复草稿，以及经授权的发送。
- 日历与待办：从会话或邮件提取事项，展示时间、时区、对象和来源，再创建或修改。
- 定时自动化：支持用户明确设置的计划和触发条件，提供查看、暂停、取消与执行记录。
- 用户委托范围是自动化边界；持续监控属于显式创建的计划，不由普通对话悄然开启。

### 4.6 社交账户与购物平台

- 社交账户：连接与权限管理、授权内容整理、草稿生成、发布准备，逐步增加实际平台操作。
- 购物平台：商品搜索与比较、条件筛选、候选清单、授权订单信息读取；交易动作作为单独能力评估与交付。
- 每个平台单独声明已支持的读写操作。连接成功不代表所有动作都可执行，实际能力以已集成接口及授权范围为准。

### 4.7 历史、知识与记忆

- 基础能力：保存对话历史、关键执行记录与产物引用，支持继续已有工作。
- 扩展能力：用户偏好、项目事实、个人知识库检索和跨会话关联。
- 长期记忆应支持用户查看、更正与删除；不把所有历史原文自动视为长期有效事实。
- 记忆和检索结果按当前需求装配，来源与时效有据可查。

### 4.8 权限、审批与执行可见性

- 用户能查看哪些目录、账户与操作已获授权，并可撤销授权。
- 审批展示具体操作对象、参数或内容，授权只用于相应操作及范围。
- 执行界面展示关键步骤、工具进度、等待原因、失败原因和结果文件。
- 取消、撤销文件变更、撤销外部动作是不同能力，分别反馈；已发送邮件或已下单不能用「文件撤销」恢复。

## 5. 功能优先级与阶段范围

优先级定义：P0 为本地首版闭环；P1 为首版后的个人生产力扩展；P2 为多用户云端与更广平台能力。下表是建议范围，不构成未经验证的开发工期承诺。

| 功能 | P0：本地首版 | P1：个人工作流扩展 | P2：云端与规模化 |
|---|---|---|---|
| 会话与多轮交互 | Web 输入、历史、流式输出、取消 | 更完善的检索与项目关联 | 多端一致访问 |
| 文件与产物 | 受管工作区、版本、ChangeSet、附件 | 更多格式、外部目录适配 | 对象存储与跨设备引用 |
| 工具执行 | 文件工具、已配置的基础搜索/fetch | MCP、浏览器与专门工具 | 独立工具池与资源调度 |
| 编程辅助 | 文件生成与修改；隔离执行就绪后开放运行 | 更完整的项目检查流程 | 按需云沙箱 |
| 持久执行 | SQLite 作业、可恢复状态、事件补发 | 更长任务与失败恢复优化 | 分布式队列、租约、池化 Worker |
| 业务任务管理 | 可选关联，无强制意图拆分 | 跨轮目标与完成证据 | 多任务协同与并行分支 |
| 邮件/日历 | 不作为首版交付前提 | 优先接入一组具体服务 | 扩展服务与多账户 |
| 社交/购物 | 不作为首版交付前提 | 草稿与比较等选定场景 | 按平台逐项接入动作 |
| 定时自动化 | 预留触发入口 | 本机可运行时执行，展示错过策略 | 云端持续调度 |
| 记忆与知识库 | 会话上下文与文件引用 | 可管理的偏好、项目记忆与检索 | 多端同步与权限隔离 |

本机服务关闭时不承诺定时执行；开启后需按明确策略补执行或标记错过。云端后续可在设备离线时执行纯云任务，但本机操作仍需等待设备在线。

## 6. 统一用户体验

### 6.1 核心交互闭环

用户选择工作空间并描述需求 → 应用接收并展示状态 → 助理按需读取资料、规划和调用工具 → 遇到缺失信息或授权要求时等待 → 交付回答、文件或操作结果 → 用户查看证据并继续修改。

UI 的用户用语优先采用「会话、执行进度、文件、变更、待确认」，不要求用户理解 RunAttempt、Checkpoint 或队列。

### 6.2 状态表达

| 用户看到的状态 | 含义 | 可用动作 |
|---|---|---|
| 已接收/排队中 | 请求已持久保存，等待执行 | 查看、取消 |
| 执行中 | 正在模型决策、工具操作或生成内容 | 查看进度、请求停止 |
| 等待你补充 | 缺少继续执行所需的信息 | 回答、取消 |
| 等待你批准 | 某个具体操作需要确认 | 查看详情、批准或拒绝 |
| 等待设备/服务 | 当前依赖不可用 | 查看原因、等待或取消 |
| 已交付 | 本次结果已生成，有明确产物或回答 | 查看、继续修改 |
| 部分完成/失败 | 有未完成目标或执行错误 | 查看已完成部分、重试或调整 |
| 结果待核对 | 外部操作可能已生效，尚未确认 | 核对实际状态，避免重复操作 |

页面断线不是执行失败；「已交付」也不代表用户主观满意。产品只在有对应证据时声明操作成功。Task 是否完成以约定目标和验收条件判断，不能用用户不再提及来推断。

## 7. 设计目标与验收要求

| 编号 | 设计目标 | 产品要求 | 验收依据 |
|---|---|---|---|
| G1 | 完成真实工作 | 每类核心场景有可使用的结果 | 文件可打开、代码检查有输出、草稿可编辑 |
| G2 | 过程可理解 | 状态、等待原因和失败不含糊 | 界面与实际执行状态一致 |
| G3 | 结果可追踪 | 回答、工具动作和文件版本能关联 | 从产物可追溯到输入和变更记录 |
| G4 | 用户可控制 | 权限明确，审批绑定操作，可请求停止 | 未授权操作被拒绝；取消反馈真实 |
| G5 | 工作可持续 | 页面刷新、连接中断不丢已接收工作 | 历史可恢复，事件可补读 |
| G6 | 修改可管理 | 受管文件有版本与冲突检测 | 撤销不覆盖后续修改，旧附件内容稳定 |
| G7 | 上下文连续 | 后续输入能继续已授权的项目与产物 | 无需重复提交全部资料，且不串会话 |
| G8 | 资源可约束 | 模型、工具、存储、执行时间有预算 | 到限额停止或提示，不无限重试 |
| G9 | 部署可演进 | 本地验证的业务契约可迁移到云端 | ID、事件、文件引用及状态含义保持一致 |
| G10 | 数据使用透明 | 区分本地存储、模型上传与账户访问 | 用户能理解哪些数据会被何种操作使用 |

交互延迟、任务成功率和资源成本应在固定模型、工具与硬件条件下测量后建立基线。首版不写未经压测的并发承诺或固定成功率；记录请求确认耗时、首个有效反馈时间、总耗时、失败分类与单次执行成本，供后续设定服务目标。

## 8. 产品概念与技术设计的对应

| 产品概念 | 技术对象 | 统一约定 |
|---|---|---|
| 一段对话 | Session | 保存对话与事件流，可涉及多个目标 |
| 一条输入/回复 | Message | 保存语义内容及来源关系 |
| 一轮响应 | Turn | 输入引起的用户可见响应单元 |
| 一次执行 | Run | 可包含等待、审批与恢复，不随浏览器连接消失 |
| 跨轮目标 | Task | 可选；一个消息不必强制创建一个 Task |
| 操作记录 | Event / ToolCall | 记录发生了什么，以及由何次执行引起 |
| 工作空间 | Workspace | 文件和权限的逻辑边界，不等于常驻云电脑 |
| 交付文件 | Artifact / FileVersion | 引用固定内容版本 |
| 一组文件修改 | ChangeSet | 记录前后版本及来源，支持有条件撤销 |
| 待确认动作 | Approval | 绑定具体请求，而非笼统授予后续所有权限 |

Runtime 引擎负责推进决策与工具调用；产品层负责需求承接、领域状态、用户可见事件、文件版本、授权和交付。框架的内部 todo、工具名或 checkpoint 不直接定义产品里的 Task、文件历史和完成状态。

## 9. 本地与云端方案共同遵守的原则

| 方面 | 本地方案 | 云端方案 | 不变的产品要求 |
|---|---|---|---|
| 执行承载 | 一个后端进程内的 Runtime | 共享 Runtime Worker 池 | 执行身份、状态和结果可追踪 |
| 用户入口 | 本地 Web 页面 | 桌面、手机、Web | 统一会话、审批与产物体验 |
| 数据存储 | SQLite 与本地文件 | 数据库与对象存储 | 语义历史、文件版本和引用稳定 |
| 设备操作 | LocalDeviceAdapter | Device Agent 与设备网关 | 端侧权限不能被绕过 |
| 代码运行 | 按需本地隔离环境 | 按需云沙箱 | 执行环境与持久工作数据分离 |
| 事件返回 | API 内置 SSE endpoint | 可独立部署的 SSE 服务 | 持久化、重连补发、断线不取消 |
| 资源管理 | 单机限制 | 用户配额与共享资源调度 | 不无限占用，超限有明确反馈 |

本地版不是与云端版无关的演示程序。先保留清晰的模块接口与领域关系，后续按需要替换存储和执行承载；不为了未来微服务拆分提前引入全部分布式组件。

## 10. 数据、授权与产品边界

1. **访问边界**：只操作明确授权的目录、设备与账号；首版以受管工作空间为主要范围。
2. **数据出站**：本地存储不等于所有处理都在本地；远程模型与工具请求的数据流需有配置说明，敏感内容按策略处理。
3. **外部资料**：网页、邮件和文档是待处理内容，不能因其中出现指令就获得新权限或改变用户授权。
4. **外部动作**：读取、生成草稿、发送、发布和购买是不同权限。执行前后的状态必须准确，未知结果先核对。
5. **撤销边界**：受管文件可通过新变更恢复旧版本；外部副作用只能依赖相应平台的补偿能力，不承诺通用撤销。
6. **删除与保留**：区分删除会话、删除产物、删除历史版本和撤销连接；产品需说明影响范围，备份与保留策略也应一致。
7. **能力声明**：每个连接器和文件格式按实际实现列出能力；不以“支持工具扩展”代替已实现的功能。

## 11. 非目标与明确限制

- 首版不追求覆盖所有邮件、社交、购物与办公平台。
- 不承诺任何用户需求都能自主完成；遇到权限、能力或信息限制时明确说明。
- 不要求每条消息先完成复杂的意图拆分与历史 Task 关联。
- 不为每个用户配置永久运行的云电脑，也不为普通问答启动沙箱。
- 不承诺任意宿主机文件变化均可撤销，或任意进程状态都能无损恢复。
- 不以模型声明代替工具实际结果，也不把生成了计划当作完成了工作。

## 12. 路线与阶段出口

### 阶段一：完成本地核心闭环

建立 Web 输入、Deep Agents 执行、SQLite 持久状态、SSE 输出、文件版本、产物和审批。优先打通资料处理与受管项目编辑。代码运行在隔离执行就绪后开放。

阶段出口：一个真实需求可从输入推进到可查看产物；重开页面可恢复历史；文件变更可追踪；审批和取消有效；关键故障不会静默丢失输入或覆盖用户文件。

### 阶段二：形成可重复使用的个人工作流

接入一组优先的邮件/日历服务，增加定时触发、项目知识与可管理记忆，完善长任务恢复；按用户实际使用情况选择社交或购物场景。

阶段出口：用户可持续用已有项目和授权服务处理重复工作；计划可管理，失败可定位，账户操作和个人数据范围清楚。

### 阶段三：云端与多端服务

将状态、事件与文件存储迁移到云端服务，拆分 Runtime Worker、工具池与沙箱，接入 Device Agent，增加多用户隔离、配额和运维能力。

阶段出口：多用户、多设备并发下保持数据隔离和一致体验；Worker/设备断线有明确恢复路径；资源成本与服务质量可衡量。

## 13. 产品衡量与首版验收清单

核心价值指标建议采用「用户实际使用或继续编辑的有效交付数量」，结合用户反馈与客观产物证据衡量；不以模型调用次数或 token 数衡量价值。统计应区分场景难度，失败与部分完成不能被归为成功。

辅助指标包括：目标达成率、用户修正次数、重复操作率、来源可追踪率、恢复成功率、文件冲突数、审批拒绝原因、单次交付时间与成本。用户确认可以作为反馈证据，但不是所有 Task 结束的强制节点。

首版必须验证：

- [ ] 重复提交同一请求，不创建重复逻辑执行。
- [ ] 刷新或断开页面后，可补读输出并查看最终结果。
- [ ] 不同会话的上下文和产物不会意外串用。
- [ ] 工具失败与执行结果未知能被正确区分。
- [ ] 审批只授权对应操作，拒绝后不执行。
- [ ] 文件版本关联实际输入、工具调用和输出事件。
- [ ] 用户后续修改不会被撤销操作静默覆盖。
- [ ] 进程崩溃后可恢复、对账或明确报告不能恢复。
- [ ] 未接入的平台与未实现的动作有明确能力提示。
- [ ] 用户能够完成一个真实的资料或代码处理流程并使用交付物。

## 14. 后续决策记录

尚需在实现和试用中确认的事项：首批模型与预算、优先支持的文档格式、第一组邮件/日历服务、代码沙箱方案、历史版本保留时长、云端上线前的数据迁移和删除政策。这些选择不阻塞本地核心闭环设计，但必须在对应能力发布前确定。
